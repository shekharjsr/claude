# PSS 2.0 — Roadmap

This document tracks where the project is, what's being worked on, and what's planned. It will be updated as priorities shift.

---

## shipped

**Multi-cloud telemetry ingestion**
Real-time energy and workload data pulled from AWS CloudWatch and Azure Monitor into a unified pipeline. Handles the normalization differences between the two providers without requiring teams to change how they instrument their services.

**Carbon intensity grid integration**
Hourly carbon intensity feeds integrated per AWS and Azure region. Workloads are scored against live grid data, not static averages, which matters because grid carbon intensity can vary by 3–4x across a single day in some regions.

**Workload-level emission attribution**
Every workload running across the fleet gets a carbon cost attached to it, updated continuously. Engineering teams can see their footprint the same way they see their cloud bill.

**AI-powered shift recommendations**
When a workload is running in a high-carbon window or region, PSS 2.0 generates a specific recommendation with estimated savings and trade-offs. Implemented with Claude (Anthropic) for both the reasoning layer and the plain-language output that non-technical stakeholders can act on.

**Emission summary reporting**
Automated weekly briefs covering what changed, what improved, and where the biggest remaining opportunities are. Generated by Claude from raw telemetry, readable by sustainability leads without needing an analyst to interpret it.

---

## in progress

**GCP support**
Extending the telemetry ingestion layer to Google Cloud Platform. Architecture is defined; implementation is underway with expected completion Q3 2026.

**Scheduling-aware recommendations**
Currently recommendations are region and instance-type based. Adding time-of-day scheduling as a dimension — shifting batch workloads to low-carbon grid hours rather than just low-carbon regions.

**Self-serve dashboard**
A lightweight UI for team leads to explore their workload footprint without needing to go through the central platform team. In design phase.

---

## planned

**Open-source release of core components (Q1 2027)**
The telemetry ingestion layer and carbon intensity grid integration will be released as open-source under Apache 2.0. These are the parts most reusable by other teams running multi-cloud infrastructure. The PSS 2.0 team (20 engineers) will maintain them going forward.

**Terraform module for self-hosted deployment**
Packaging the core platform as a Terraform module so other organizations can deploy it into their own AWS/Azure accounts without a long setup process.

**Public carbon intensity API**
An open API wrapping the regional grid data we're already consuming internally. Other developers building emission-aware tooling shouldn't have to solve this integration problem from scratch.

**Scope 3 emission tracking**
Extending beyond direct cloud infrastructure to include upstream supply chain and data transfer emissions. Longer term, but on the roadmap as enterprise sustainability reporting requirements tighten.

---

## not planned (for now)

- On-premise / private data center support (out of scope for this project)
- Financial cost optimization (there are better tools for this; PSS 2.0 stays focused on carbon)
- Real-time alerting (planned for a future version, not the current cycle)
